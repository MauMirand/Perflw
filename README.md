# Perflw

An offline-first Electron desktop planner with local accounts: calendar, projects, routine, learning (study files turned into notes, key points and grounded answers), chat and AI agents. The interface follows the dark "Planner app" design: an icon rail, a custom window bar, a collapsible sidebar and a rounded main panel.

Everything runs on your own computer. AI features use a local [Ollama](https://ollama.com) by default; cloud providers (OpenAI, Anthropic, Gemini, OpenAI-compatible) are optional and use your own key.

## Requirements

- Windows 10 or 11 (the app is developed and packaged for Windows x64)
- [Node.js](https://nodejs.org) 22 or newer
- Optional, for the AI features: [Ollama](https://ollama.com) with
  - a chat model, for example `ollama pull qwen2.5:7b`
  - an OCR model for pictures in study files, for example `ollama pull glm-ocr:q8_0`
- Optional: Microsoft Office, for exact Word and PowerPoint previews

## Run and build

```powershell
npm install
npm start
npm test
npm run test:electron
npm run test:learning
npm run build
```

Open `dist\Perflw-win32-x64\Perflw.exe` after building. Run `npm run setup:windows` to refresh the desktop shortcut.

## Your data

Nothing you create is stored in this repository or sent anywhere by default. Accounts, study files, notes, chats and settings stay in the app's data folder on your computer (`%APPDATA%\Perflw`); API keys are encrypted with Windows' own protection (Electron `safeStorage`). Study files are only sent to an AI provider you choose; with the default local Ollama they never leave the computer.

## What's in the app

- **Window**: frameless window with its own minimize / maximize-restore / close buttons; drag or double-click the top bar to move or maximize.
- **Rail**: logo, Account menu (profile, settings, sign out), Home, New (plan, whim, routine step, activity, conversation), Search (Ctrl+K), Chat, Settings.
- **Sidebar**: Planner (Calendar, selected-date card, Projects), Daily (Routine, Learning, Activities, Analytics) and Automation (Workflows, Agents, Skills). Collapses to an icon rail with tooltips (Ctrl+B); the choice is remembered.
- **Calendar**: Days / Weeks / Months views with previous/next/Today navigation. Plans belong to a date and may have a time. Click a day to select it, double-click to open it in Days view, click an empty time slot to add a plan at that hour. The right-hand plan panel lists the selected day's plans with colour accents, completion checkboxes, inline editing (click the text), removal with Undo, and a progress bar. In Days and Weeks, schedules (`events`) are drawn as time blocks at their real length: click an empty time for a 1-hour block, drag for any length (15-minute snap), click or right-click a block to edit it. Tasks, milestones and schedules created from a project page appear on the Calendar and open their project.
- **Projects** (the `whim` view): pages with an open-tab strip and a block editor — paragraph, to-do, bullet, numbered, toggle, quote, callout, code, divider, image, bookmark, table, tasks, milestones, schedule and related blocks — with `/` to pick a block type and undo. Rules live in `src/project-model.js`, the editor in `src/projects.js`.
- **Routine**: a daily checklist; ticks reset automatically each day.
- **Learning**: subjects, kept per learning profile — click the profile name beside the title (or see it in the sidebar) to switch between *study* and *personal*. The **+** pocket creates a subject (image, name, Major/Minor type, mastery %, time spent, description); each subject pocket shows its image and name, with **⋯** to edit or delete. Click a pocket once to open the right-hand preview panel (image as the cover, details, and placeholders for topics and mastery statistics; the panel button closes it), double-click (or Enter on a previewed pocket) to open the subject as a full page. Code: `src/learning.js`, `src/learning.css`.
  - **Topics** (on the subject page; the preview panel shows a read-only list): a numbered list in order, filled from uploaded files. Numbers are never stored — they follow the order, so dragging topic 1 to place 5 makes it 5 and the others move up. Subtopics are numbered 2.1, 2.2 under their topic, and a topic drags with its subtopics. **Milestone** adds a group divider (Prelim, Midterm, Prefi, Finals, or a custom one that opens straight into rename); numbering continues across milestones. Keyboard on a focused row: Alt+↑/↓ move, Alt+→/← subtopic/topic, Enter or F2 rename, Delete removes (a topic with subtopics asks first). Rules: `src/topic-model.js`.
  - **Upload topics** (or drop files anywhere on the Topics card) reads a PDF, Word (.docx), PowerPoint (.pptx), Markdown or text file and adds its structure to the end of the list: Word Title/Heading 1 → topic and Heading 2 → subtopic; PowerPoint sections → topics with their slide titles as subtopics (without sections, slide titles → topics); PDF bookmarks (two levels); Markdown `#` / `##`. A file without that structure is added as one topic named after the file. The file is kept under `learning-files/<account>/` in `userData` with its readable text (Word, PowerPoint, Markdown, text; PDF text is read by the Learning document workflow below); it is removed with its last topic or its subject. Reader: `src/learning-import.js` (no dependencies; 25 MB limit).
  - **Topic viewer**: click a topic (on the subject page or in the preview panel; Enter on a focused row) to open its file inside the app. Left: the topic navigator, grouped by milestone. Middle: the file, scrollable. Right: the notes panel and the Ask panel of the Learning document workflow (below). **Learning** returns to the subjects, the subject chip to the subject page, Escape too. Rename a topic with its pencil button or F2.
    - PDFs open in the app's own PDF viewer (`src/learning-pdf.js`, pdf.js): the file is read once per document through IPC (`learning:fileBytes`, signed-in account only), its pages fit the width and are drawn as they scroll into view, and text can be selected. Opening a topic, or clicking a key point, section or answer source, scrolls the same view (no reload) to the page and to the exact words, which are highlighted.
    - Word and PowerPoint files: Microsoft Office saves a PDF copy in the background after upload (Windows, Office installed; the original is opened read-only), so they show exactly as in Office. PowerPoint topics open at their slide; Word topics get their page from the heading bookmarks Word writes. Until the copy is ready the viewer says so; without Office, or if Office fails, the viewer shows the file's text with a Try again button.
    - Markdown and text files are drawn as a page in the app and scroll to the topic's heading.
  - **Learning document workflow** (`src/learning-workflow.js`, `src/learning-intel.js`, `src/learning-agents.js`, panels in `src/learning-study.js`): every uploaded PDF, Word, PowerPoint, Markdown or text file goes through one pipeline in the main process, one file at a time:
    1. *Direct conversion*: the file becomes typed blocks — title, headings (levels 1–3), paragraphs, list items — with their page or slide. Word styles and outline levels, PowerPoint slide titles, sections and bullet levels, PDF text with headings from bookmarks and font sizes (via `pdfjs-dist`; repeated page headers/footers dropped), Markdown `#`, and heading patterns in plain text.
    2. *Pre-analysis*: sections numbered 1, 1.1, 1.1.1; per section a one-sentence description and ranked key points (definitions, emphasis, numbers, bullets); document main points and keywords; text chunks for questions.
    3. *Notes file*: `docs/<id>.md` per document. A new upload whose name is similar to an existing document (same words and numbers, ignoring `v2`, `final`, `(1)` …) **updates** that `.md`; otherwise a new one is **created**. Each `.md` names the subject information center file.
    4. *File Data and Information Center*: `SUBJECT.md` lists every document of the subject with its source files, outline and main points, plus the notes saved from answers. All of it lives under `learning-files/<account>/intel/<subjectId>/` in `userData` and is removed with its files or subject.
    5. *Pictures* (`src/learning-images.js`): the **Learning Image Reader** reads the pictures in a file, so slides, infographics, tables and scanned pages reach the notes and answers. That covers pictures in Word and PowerPoint files, PDF pages that draw a picture (rendered as a whole page), and PNG/JPG/WebP files uploaded as a topic of their own. Icons smaller than 160 px and logos repeated on many slides are skipped. Pictures larger than 1,280 px are scaled down first.
       - **Models**: it prefers a small local OCR model (`ollama pull glm-ocr:q8_0`, 0.9B, about 1.8 GB; it fits a 4 GB GPU and reads a dense infographic in about 15 s), called directly with *Text Recognition*. Its plain text is turned back into structure: capital-letter panel headings, `Label:` sub-headings, bullets and table rows such as `CSR (voice) 80 100 +20`. A general vision model (for example `qwen2.5vl:7b`) or a cloud provider set on the Agents page uses the skill *Learning image reading* instead. A Reader on a general vision model that the app chose itself moves to an OCR model once one is installed; a model chosen on the Agents page is kept.
       - **Notes**: each reading is cached by the picture's content hash and goes where the picture sits. A section shows it whole under *From the picture*, in the notes panel and in the `.md`; a slide titled only "Slide 7" takes the picture's title. Each picture's text shows as soon as it is read, and a question in the Ask panel goes before the next picture. Questions such as "what is page 7 about" or "slide 17" use that page's sections and pictures.
    6. *AI overview*: the **Learning Document Analyzer** agent (skill *Learning key points*) adds a short overview and key ideas to the `.md` and the notes panel.
    - **Notes panel** (viewer, top right): the open file's title and its key points numbered 1, 1.1, 1.2 …, with the open topic's section highlighted; click a section to open that part. The **Notes** tab holds notes saved from answers (delete with ×). The file button opens the `.md`.
    - **Ask panel** (viewer, bottom right): questions go to the **Learning Subject Assistant** agent (skill *Learning grounded answers*) with excerpts found in the information center only. Answers cite their excerpts ([1], [2] — click to open that part) and up to three notes are saved. If nothing is found, or the agent replies `NOT_IN_FILE`, a 2nd, broader run searches every file of the subject; if that also finds nothing the panel warns *“Your question regarding the file is not included in the file.”* Questions such as “Summarize this file” use the file's outline and main points. Casual messages (“hi”, “thanks”, “who are you?”) get a short normal reply with no lookup. If the AI model cannot be reached, answers fall back to the matching sentences from the files, with a notice. Answers can be stopped.
    - Clicking a section or key point in the notes panel (or a source under an answer) opens that file at the page it comes from (PDFs, and Word/PowerPoint shown through their Office PDF copy; Word pages are read from that copy), or scrolls to and highlights the text on text pages. Slide-deck PDFs are read one section per slide, with running headers dropped.
    - The two agents and two skills are created on first use, are ordinary editable packages on the Agents and Skills pages, and are created again if deleted. They use local Ollama (the largest available chat model up to 14B); choose another provider on the Agents page. Without any model, the notes panel still works and answers are the matching sentences from the files, marked as such.
  - Study sessions and quizzes are not built yet; Mastery Statistics is a placeholder.
- **Activities**: log what you did, grouped by day.
- **Analytics**: routine completion today, activities logged, plans this month, projects kept, plus 7-day charts for activities and completed plans.
- **Chat**: conversations with saved messages, categories (Work, Learning, Personal), rename, archive/unarchive and delete. Each conversation has its own model, optional workflow, skills, instructions, context and memory notes. The engine (`src/automation/chat.js`) runs each turn as a slash command (changes the session, no model call), through the attached workflow, as one direct reply (with tools when the agent allows them), or as a planned multi-step answer that is checked against the request. Replies stream and can be cancelled; Markdown, code, charts, flow diagrams and option pickers render inline (`src/chat-render.js`).
- **Agentic Automation (Workflows)**: a node canvas for building AI pipelines. Blocks: Input, AI Agent, Markdown instructions, Output. Drag blocks to move them, drag from a port to connect, scroll to zoom, drag the background to pan. Selecting a block opens its settings (agent choice, extra instructions, input mapping with `{{input}}` / `{{prompt}}`, Markdown editor with `.md` import and preview, connection list). Undo/redo, duplicate, delete, autosave plus Save (Ctrl+S). The Test panel on the right runs the connected workflow from Input to Output and shows each step, live agent text, logs, errors and the final output; Run becomes Stop while it is working. Workflows can be created, renamed, duplicated, reopened and deleted from the Workflows menu.
- **Agents**: each agent has an editable package of files (`identity.md`, `instructions.md`, `capabilities.md`, `context.md`, `configuration.json`, `resources/`) shown in an Overview and a Files tab, with unsaved/saved state, validation and kept file history. Create, edit, duplicate, delete (to trash), import and export agents (exports never contain API keys). Each agent picks a provider and model, its skills, its permissions (file read/write, documents, web, external APIs, workflow interaction, code execution, skill scripts — all off by default) and a context budget. The runtime reads the saved files on every run. **LLM APIs** (button on the Agents page) adds OpenAI, Anthropic, Google Gemini or a custom OpenAI-compatible endpoint next to the built-in local Ollama, with connection tests and model discovery; keys are encrypted with `safeStorage` and never shown again.
- **Skills**: reusable packages (`SKILL.md` with front matter, `references/`, `scripts/`, `resources/`) that can be shared by several agents. Create, edit files, enable/disable, duplicate, delete, import and export; the page shows which agents use each skill. Only skill descriptions are sent until a skill matches the task; then its instructions load, and references load only when they match. Scripts never run on their own: they need the agent's "Run skill scripts" and "Code execution" permissions and your approval each time. Workflow Agent nodes can override the skills for one step, and each run step shows which agent, provider/model, skills and context parts were used, with estimated and provider-reported token counts.
- **Settings**: banner theme or image, reduce motion (Auto/On/Off), week start (Sunday/Monday), 12/24-hour time, default calendar view, profile photo, sign out, version.

## Data

Accounts, scrypt password hashes, profiles and session hashes live in SQLite under Electron's `userData` directory; the active session token is encrypted with Electron `safeStorage`. Workspace records live in `workspace.sqlite`, scoped to the signed-in account:

- `planner_items` — plans (`day`, optional `time`, `done_on`), whims, routine steps (`done_on` = the day they were ticked) and activities.
- `chat_sessions` and `chat_messages`.
- `agents` and `workflows` — a workflow stores its title, description and graph (blocks, positions, settings, connections, canvas view) as JSON. Test conversations are kept only while the app is open.
- `provider_connections` — LLM API connections; API keys only as `safeStorage` ciphertext. Agent packages and skills live as files under `agent-ecosystem/<account>/{agents,skills}/` in `userData` (deleted packages move to `.trash/`, overwritten files to `.history/`). Existing agents are migrated into packages the first time they are listed; their database rows are kept.

Learning subjects live in `subjects` (one row per subject, with its `profile`); their images are stored next to profile images. Topics and milestones live in `subject_topics` (order = `position`, `level` 0/1, `page` in the file's PDF view) and uploaded files in `subject_files` (with `preview_status` / `preview_name` for the Office PDF copy); both are deleted with their subject. Older learning goals in `planner_items` (kind `learning`) are kept but no longer shown. Projects use `projects`, `project_blocks`, `tasks`, `milestones` and `events`; Calendar time blocks use `events` and `active_timers`. Older tables (goals, ledger, finance, documents) are left untouched in the database and still have IPC handlers, but no longer have screens. Interface preferences (sidebar state, calendar view, week start, time format, motion) are stored in the renderer's local storage.

The renderer is sandboxed with Node integration disabled and a strict Content-Security-Policy; all data access goes through validated IPC in the main process.

## Project structure

- `src/main.js`, `src/preload.js`: Electron main process, window controls, authenticated IPC and the renderer bridge (`account`, `plannerData`, `workspaceData`, `windowControls`).
- `src/workspace.js`: account-scoped SQLite schema and validation.
- `src/index.html`, `src/styles.css`, `src/renderer.js`: the interface.
- `src/automation.js`: the workflow editor (registers the `automation`, `agents` and `skills` views). `src/ecosystem-ui.js`: the Agents, LLM APIs and Skills screens.
- `src/automation/engine.js`: node-type registry, connection rules and the execution engine. Loaded by both the main process and the renderer. Execution order comes only from connections; only blocks reachable from Input run; loops are rejected. To add a block type (condition, transform, file, delay…), add an entry to `NODE_TYPES` with its ports, `cleanConfig` and `execute`.
- `src/automation/providers.js`: provider adapters (Ollama via `ollama.js`, OpenAI, Anthropic, Gemini, OpenAI-compatible) behind one `listModels`/`chat` interface, with capability flags and key-redacting errors. `src/automation/connections.js`: encrypted provider connections.
- `src/automation/ecosystem.js`: joins agent packages, skills, providers, context assembly (`context.js`) and permission-checked tools (`tools.js`); `runAgent` is what Agent nodes call. `src/automation/packages.js`: agent and skill package storage and validation.
- `src/automation/store.js`: account-scoped storage for agents and workflows.
- `assets/fonts`: Inter (OFL) and Roboto.
- `test/`: unit tests (`auth`, `workspace`, `planner`, `learning`, `learning-workflow`, `topics`, `projects`, `chat`, `chat-render`, `automation`, `ecosystem`, `ecosystem-intelligence`), the Electron end-to-end check (`electron-smoke.js`), the workflow check (`automation-smoke.js`) and the Learning document workflow check (`learning-study-smoke.js`, `npm run test:learning`; fixtures in `test/fixtures/learning/`).
- `scripts/build.js`: Windows packaging (`npm run build`): leaves out tests, docs and unused pdf.js builds, keeps only the en-US Chromium locale, and unpacks the `@napi-rs/canvas` native module from the asar. `scripts/setup-windows.ps1`: desktop shortcut and folder icon. `scripts/launch-prototype.vbs`: starts the development app with separate prototype data.
- `docs/`: product concepts, specifications and research notes.

## Checks

`npm test` covers accounts, sessions, workspace isolation, the planner/chat stores, the automation engine, store and Ollama adapter, and the agent ecosystem (`test/ecosystem.test.js`: package migration and editing, encrypted keys, provider wire formats and errors, progressive skill loading, permissions/approvals, context budgeting, workflow integration). `npm run test:automation` drives the real app through building, running, cancelling and reopening a workflow using a local Ollama model (it exits with code 2 if Ollama or a local model is unavailable). `npm run test:pdf` checks the PDF viewer (every key point lands on its own page and words, in the same view, quickly; rapid clicks end on the last one) and that a streamed Ask reply never redraws or re-animates the thread (it needs port 11434 free: it starts a stand-in Ollama). `npm run test:electron` drives the running app: register, profile setup, plans in all three calendar views, whims, routine, activities, analytics values, chat lifecycle, profile editing, settings, search, menus, sidebar collapse, restart persistence, and sign out/in. Set `PERFLW_SCREENSHOT_DIR` to an absolute folder to save screenshots.
